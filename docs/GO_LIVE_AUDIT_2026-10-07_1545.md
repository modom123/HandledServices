# Go-live audit: Stripe and readiness (2026-10-07)

**Checks:** 83/83 core tests pass. Typecheck is clean. The production build passes.

## Fixed in this pass
| Issue | Fix |
|---|---|
| A pro who was only *offered* a job could cancel it, raise its price, change its photos or get its payment link through the customer endpoints | All customer job actions now require `customer_id = signed-in user` (cancel, raise, counters, photos, pay, review, track) |
| A failure while applying a Stripe payment was silently lost (the retry was skipped as a duplicate) | It now raises a critical Hub alert, and a dispatch error no longer interrupts payment processing (the dispatch cron retries) |
| The webhook setup instructions left out `payment_intent.succeeded` (app payments) and the Stripe Identity events | Hub → Setup now lists every event the code uses |
| Open redirect on the language switch (`/api/lang?next=/\evil.com`) | Uses the shared `safeNext()` check |

## Still to fix in code (next pass)
**Before real money**
1. **Payment links that last.** Stripe Checkout links expire after 24 hours. Net-30 invoices and balance emails need a stable `/pay/<id>` link that creates a fresh checkout when clicked.
2. **No double payments.** If a customer pays an old link and a new one, both are kept. The fix is to refund the extra automatically, or alert staff, once a job is already paid in full.
3. **Remedy refunds on deposit jobs.** These refund only the first payment. Switch them to `refundAcross` so they span every payment.
4. **`charge.refunded` handler.** Refunds made in the Stripe dashboard should update the job, the pro's payout, partner commissions and loyalty points.
5. **Payout safety.**
   - Narrow the `try` so a failure *after* a transfer can't send the same payout again.
   - Return the 1.75% instant-pay fee when the instant payout fails.
   - Check the Stripe balance before the weekly run. Card money takes about 2 days to settle in early live mode.
6. **Dispute de-duplication.** A repeated `charge.dispute.closed` currently creates two pro deductions.
7. **No pros in an area.** Paid bookings in an area with no approved pros dead-end, and ZIPs outside every market can be booked. Block or waitlist those ZIPs, and make sure each launch service has at least one approved pro.

**Before launch (not money)**
- SMS consent text at the phone field (TCPA / Twilio A2P 10DLC registration).
- Footer links to Terms of Use and /terms. Add an accessibility statement, a cookie notice, a contact page and the business postal address.
- Branded 404 page, `metadataBase`, and fix robots/sitemap falling back to localhost.
- Rate limit on owner sign-in codes.
- Hub → Setup checks for the newest database updates (loyalty points, bid measurements).
