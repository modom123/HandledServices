# Building the Handled mobile app (v0.2.0)

Checked on 2026-10-02: JS bundles compile for Android and iOS, native prebuild succeeds, and the
location permission is in both apps (Android ACCESS_FINE/COARSE_LOCATION; iOS
"When in use" message). Builds run on Expo's servers (EAS), from your computer.

## One-time setup (about 10 minutes)

1. Install the tools: `npm install -g eas-cli` and sign in: `eas login` (free Expo account).
2. From `apps/mobile`: `npm install`, then `eas init` — this creates the Expo project and writes
   the real `projectId` into `app.json` (replacing "run `eas init` to fill this in"). Commit it.
3. Set the app's environment for builds (Expo dashboard → Project → Environment variables, or
   `eas env:create`):
   - `EXPO_PUBLIC_API_URL` = your website URL (e.g. https://handled.example)
   - `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` = from Supabase → Settings → API

## Build

From `apps/mobile`:

| What you want | Command | Result |
|---|---|---|
| Test on Android phones now | `eas build -p android --profile preview` | An .apk link you can install directly |
| Test on iPhones | `eas build -p ios --profile preview` | Needs an Apple Developer account ($99/yr); install via the link on registered devices |
| Store release | `eas build -p all --profile production` | .aab for Google Play, .ipa for the App Store (build numbers auto-increment) |
| Submit to the stores | `eas submit -p android` / `eas submit -p ios` | Uploads the latest production build |

## Why a new build (not just an update)

v0.2.0 adds a native module (expo-location) and a new phone permission, so the app has to be
rebuilt and reinstalled. After this, JavaScript-only changes can ship with `eas update`
(no store review).

## Before you test

- Run the latest Supabase setup or migrations (pro_roster, customer_timing_budget).
- Sign in as an approved pro → Pro tab → "On call" → allow location "While using the app".
- Hub → Live roster should show the pro On call with a live location within a minute.
